# QA-TestHub - Test Strategy

## 1. Testing Approach

QA-TestHub will follow a structured manual testing approach along with API testing.

Testing will be performed based on project requirements and defined test cases.

---

## 2. Functional Testing

Functional testing will verify whether each application feature works according to the requirements.

Examples:

- Login functionality
- Requirement creation
- Test case management
- Bug creation
- Test execution
- API requests

---

## 3. Negative Testing

Negative testing will verify application behavior when invalid or unexpected inputs are provided.

Examples:

- Invalid login credentials
- Empty required fields
- Invalid email format
- Invalid API request

---

## 4. Regression Testing

Regression testing will be performed after changes to verify that existing functionality has not been affected.

---

## 5. API Testing

Postman will be used for API testing.

The following will be validated:

- HTTP status codes
- Response data
- Positive API scenarios
- Negative API scenarios

---

## 6. Defect Management

Defects will be documented with:

- Bug ID
- Bug Title
- Description
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Status

---

## 7. AI-Assisted Testing

AI-assisted prompts will be used to generate:

- Test cases
- Test scenarios
- Negative test cases
- Boundary test cases
- Bug analysis suggestions

AI-generated results will be reviewed manually before using them for testing.

---

## 8. Cross-Browser Testing

The application will be checked on supported web browsers to identify UI or functionality differences.

---

## 9. Test Data Management

Valid, invalid, boundary and negative test data will be used to achieve sufficient test coverage.

---

## 10. Defect Reporting Process

Identified defects will be recorded, reviewed and tracked through their lifecycle:

Open → Fixed → Retest → Closed
